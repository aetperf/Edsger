API reference¶

All the classes can be imported from the package, as in from edsger import Dijkstra. They are defined in the edsger.path module, except ConnectedComponents (edsger.components), MinimumSpanningTree (edsger.spanning_tree) and Centrality (edsger.centrality). This page is generated from the docstrings.

Dijkstra’s algorithm, for the shortest paths in a directed graph with non-negative edge weights.

The graph is built once from a dataframe of edges. The run method can then be called any number of times, from or to different vertices.

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types.

  • tail (str, optional (default='tail')) – Name of the column with the tail (start) vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head (end) vertex of each edge.

  • weight (str, optional (default='weight')) – Name of the column with the edge weights. Negative and NaN weights are rejected with a ValueError, whatever the value of check_edges.

  • orientation ({'out', 'in'}, optional (default='out')) – ‘out’ for the paths from one vertex to all the others (single source), ‘in’ for the paths from all the vertices to one vertex (single target).

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types, missing and non-finite values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. Without it, the internal arrays have one element per integer between 0 and the largest vertex identifier. The arguments and the results of the methods use the original identifiers in both cases. Negative identifiers are only accepted with this option, and the results must then be labelled by vertex (output='pandas' or 'polars').

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

  • lazy (bool, optional (default=True)) – Whether to use the variant of the algorithm without decrease-key operation, in which a vertex can be inserted several times in the priority queue. Both variants return the same path lengths.

Notes

When several edges have the same tail and head vertices, only the one with the smallest weight is kept.

Examples

>>> import pandas as pd
>>> from edsger.path import Dijkstra
>>> edges = pd.DataFrame(
...     {"tail": [0, 0, 1], "head": [1, 2, 2], "weight": [1.0, 4.0, 2.0]}
... )
>>> Dijkstra(edges).run(vertex_idx=0)
array([0., 1., 3.])

Compute the shortest path lengths from or to a given vertex.

Parameters:

  • vertex_idx (int) – The source vertex if the orientation is ‘out’, the target vertex if it is ‘in’.

  • path_tracking (bool, optional (default=False)) – Whether to store the shortest path tree, so that the paths can be retrieved with get_path.

  • return_inf (bool, optional (default=True)) – Whether to return numpy.inf as the path length of the vertices that cannot be reached. If False, the largest float64 value is returned instead.

  • return_series (bool, optional (default=False)) – Same as output='pandas'.

  • heap_length_ratio (float, optional (default=1.0)) – Initial capacity of the priority queue, as a fraction of the number of vertices, in (0, 1]. The queue grows when it is full, so this only changes the size of the first memory allocation.

  • termination_nodes (array-like of int, optional (default=None)) – Vertices at which to stop. The algorithm ends as soon as the path lengths of all these vertices are known, and only their path lengths are returned, in the given order.

  • output ({'numpy', 'pandas', 'polars'}, optional (default='numpy')) – Type of the result. ‘pandas’ returns a Series named ‘path_length’ indexed by vertex (‘vertex_idx’), ‘polars’ a DataFrame with the columns ‘vertex_idx’ and ‘path_length’.

Returns:

numpy.ndarray, pandas.Series or polars.DataFrame – The path lengths, as float64. Without termination_nodes, the array has one element per integer between 0 and the largest vertex identifier: element i is the length of the shortest path from the source to vertex i (‘out’), or from vertex i to the target (‘in’). The Series and the DataFrame have one row per vertex. With termination_nodes, there is one element per termination node.

Raises:

ValueError – If vertex_idx or a termination node is not a vertex of the graph, or if the graph has negative vertex identifiers and the output is ‘numpy’.

Compute the shortest path lengths from or to several vertices, in parallel.

Each vertex is a separate run of the algorithm. The runs are distributed over a pool of threads: the Cython routine does not hold the GIL.

Parameters:

  • vertices (array-like of int) – The source vertices if the orientation is ‘out’, the target vertices if it is ‘in’.

  • termination_nodes (array-like of int, optional (default=None)) – The other ends of the paths: if given, each run stops as soon as the path lengths of these vertices are known, and only these path lengths are returned. With the ‘out’ orientation, this gives an origin-destination matrix of the path lengths from vertices to termination_nodes.

  • return_inf (bool, optional (default=True)) – Whether to return numpy.inf as the path length of the vertices that cannot be reached. If False, the largest float64 value is returned instead.

  • output ({'numpy', 'pandas', 'polars'}, optional (default='numpy')) – Type of the result, see below.

  • n_jobs (int, optional (default=None)) – Number of threads. None uses all the CPUs (os.cpu_count()).

  • heap_length_ratio (float, optional (default=1.0)) – Initial capacity of the priority queue, as in run.

Returns:

numpy.ndarray, pandas.DataFrame or polars.DataFrame – The path lengths, as float64. The NumPy array has one row per vertex of vertices, and one column per integer between 0 and the largest vertex identifier, or one column per termination node. The pandas DataFrame has the same rows, labelled by vertices, and one column per vertex of the graph or per termination node. The Polars DataFrame has one row per pair of vertices, with the columns ‘origin’, ‘destination’ and ‘path_length’. The pandas index and columns are named ‘origin’ and ‘destination’ as well. With the ‘in’ orientation, vertices are the destinations.

Raises:

ValueError – If a vertex or a termination node is not a vertex of the graph, or if the graph has negative vertex identifiers and the output is ‘numpy’.

Notes

Without termination nodes, the result holds one path length per pair of vertices: 8 bytes times the number of runs times the number of vertices.

Bellman-Ford algorithm, for the shortest paths in a directed graph whose edge weights can be negative.

The graph is built once from a dataframe of edges. The run method can then be called any number of times, from or to different vertices. The shortest paths are not defined when the graph has a cycle of negative total weight: such a cycle is detected and reported.

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types.

  • tail (str, optional (default='tail')) – Name of the column with the tail (start) vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head (end) vertex of each edge.

  • weight (str, optional (default='weight')) – Name of the column with the edge weights, which can be negative.

  • orientation ({'out', 'in'}, optional (default='out')) – ‘out’ for the paths from one vertex to all the others (single source), ‘in’ for the paths from all the vertices to one vertex (single target).

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types, missing and non-finite values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. Without it, the internal arrays have one element per integer between 0 and the largest vertex identifier. The arguments and the results of the methods use the original identifiers in both cases. Negative identifiers are only accepted with this option, and the results must then be labelled by vertex (output='pandas' or 'polars').

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

Notes

When several edges have the same tail and head vertices, only the one with the smallest weight is kept.

Examples

>>> import pandas as pd
>>> from edsger.path import BellmanFord
>>> edges = pd.DataFrame(
...     {"tail": [0, 0, 1], "head": [1, 2, 2], "weight": [1.0, 4.0, -2.0]}
... )
>>> BellmanFord(edges).run(vertex_idx=0)
array([ 0.,  1., -1.])

class edsger.path.DFS(

Depth-first search in a directed graph.

The search is iterative, so it is not limited by the depth of the call stack. The edge weights are not used. The graph is built once from a dataframe of edges. The run method can then be called any number of times, from or to different vertices.

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types. A weight column, if there is one, is ignored.

  • tail (str, optional (default='tail')) – Name of the column with the tail (start) vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head (end) vertex of each edge.

  • orientation ({'out', 'in'}, optional (default='out')) – ‘out’ to follow the edges from one vertex (the search tree gives a path from this vertex to each reachable vertex), ‘in’ to follow them backward to one vertex (a path from each vertex that can reach it).

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types and missing values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. Without it, the internal arrays have one element per integer between 0 and the largest vertex identifier. The arguments and the results of the methods use the original identifiers in both cases. Negative identifiers are only accepted with this option, and the results must then be labelled by vertex (output='pandas' or 'polars').

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

  • sentinel (int, optional (default=-9999)) – Value returned for the vertices without predecessor: the start vertex and the vertices that cannot be reached. It must be a negative int32, different from all the vertex identifiers.

Notes

When several edges have the same tail and head vertices, only one is kept.

The visiting order is the one of the recursive depth-first search: from the current vertex, the search goes to its first neighbour that is not discovered yet, and backtracks when there is none. The neighbours of a vertex are taken in increasing order of their identifiers: the heads of its outgoing edges with the ‘out’ orientation, the tails of its incoming edges with ‘in’. This is also the order of scipy.sparse.csgraph.depth_first_order on a matrix with sorted indices.

Examples

>>> import pandas as pd
>>> from edsger.path import DFS
>>> edges = pd.DataFrame({"tail": [0, 0, 1], "head": [1, 2, 3]})
>>> dfs = DFS(edges)
>>> dfs.run(vertex_idx=0)
array([-9999,     0,     0,     1], dtype=int32)
>>> dfs.get_order()
array([0, 1, 3, 2], dtype=uint32)

ConnectedComponents¶

class edsger.components.ConnectedComponents(
edges,
tail='tail',

check_edges=False,

)[source]¶

Weakly or strongly connected components of a directed graph.

The graph is built once from a dataframe of edges. The run method then gives the component of each vertex, for either kind of connection.

Two vertices are in the same weakly connected component if they are connected when the edge directions are ignored, and in the same strongly connected component if there is a path from each one to the other.

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types. A weight column, if there is one, is ignored.

  • tail (str, optional (default='tail')) – Name of the column with the tail (start) vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head (end) vertex of each edge.

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types and missing values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. Without it, the internal arrays have one element per integer between 0 and the largest vertex identifier. The results are the same in both cases. Negative identifiers are only accepted with this option, and the results must then be labelled by vertex (output='pandas' or 'polars').

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

Notes

The vertices of the graph are the tails and heads of the edges. The components are numbered from 0 in increasing order of their smallest vertex: the smallest vertex is in component 0, the smallest vertex that is not in component 0 is in component 1, and so on. The labels do not depend on the order of the edges or on permute.

The weakly connected components are computed with a union-find structure, the strongly connected components with Pearce’s variant of Tarjan’s algorithm, iterative: both run in linear time, and are not limited by the depth of the call stack.

Examples

>>> import pandas as pd
>>> from edsger.components import ConnectedComponents
>>> edges = pd.DataFrame({"tail": [0, 1, 2, 3], "head": [1, 0, 1, 4]})
>>> cc = ConnectedComponents(edges)
>>> cc.run(connection="weak")
array([0, 0, 0, 1, 1], dtype=int32)
>>> cc.run(connection="strong")
array([0, 0, 1, 2, 3], dtype=int32)
>>> cc.n_components
4

A* algorithm, for the shortest path between two vertices of a directed graph with non-negative edge weights.

A* is Dijkstra’s algorithm guided by a heuristic: a lower bound of the path length from each vertex to the target. The vertices are scanned in the order of their path length from the source plus their heuristic, and the search stops as soon as the target is reached. The closer the heuristic is to the actual path lengths, the fewer vertices are scanned. The heuristic is given to run, or computed from vertex coordinates (see set_coordinates).

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types.

  • tail (str, optional (default='tail')) – Name of the column with the tail (start) vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head (end) vertex of each edge.

  • weight (str, optional (default='weight')) – Name of the column with the edge weights. Negative and NaN weights are rejected with a ValueError, whatever the value of check_edges.

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types, missing and non-finite values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. The arguments and the results of the methods use the original identifiers in both cases. Negative identifiers are only accepted with this option, and the heuristic must then be given as a pandas Series.

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

Notes

Let d(v) be the length of the shortest path from vertex v to the target, and h(v) the heuristic.

  • The heuristic is admissible if h(v) <= d(v) for every vertex v. The path length returned by run is then the shortest one.

  • It is consistent if h(u) <= w(u, v) + h(v) for every edge (u, v) of weight w(u, v), and h(target) = 0. A consistent heuristic is admissible, and each vertex is then scanned at most once.

  • An admissible but inconsistent heuristic still gives the shortest path, but some vertices may be scanned several times, which can be slow.

  • With a heuristic that is not admissible, the result is the length of a path from the source to the target, which may not be the shortest one. This cannot be detected, and no error is raised.

The zero heuristic is consistent: A* is then Dijkstra’s algorithm stopped at the target. When several edges have the same tail and head vertices, only the one with the smallest weight is kept.

Examples

>>> import numpy as np
>>> import pandas as pd
>>> from edsger.path import AStar
>>> edges = pd.DataFrame(
...     {"tail": [0, 0, 1], "head": [1, 2, 2], "weight": [1.0, 4.0, 2.0]}
... )
>>> astar = AStar(edges)
>>> astar.run(source=0, target=2, heuristic=np.array([2.5, 2.0, 0.0]))
3.0

Bidirectional Dijkstra’s algorithm, for the shortest path between two vertices of a directed graph with non-negative edge weights.

Two searches are run alternately: from the source on the outgoing edges, and from the target on the incoming edges. They stop as soon as no path through the vertices that are left to scan can be shorter than the best path found where the two searches meet.

The graph is stored in both CSR and CSC formats, which takes about twice the memory of a Dijkstra instance.

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types.

  • tail (str, optional (default='tail')) – Name of the column with the tail (start) vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head (end) vertex of each edge.

  • weight (str, optional (default='weight')) – Name of the column with the edge weights. Negative and NaN weights are rejected with a ValueError, whatever the value of check_edges.

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types, missing and non-finite values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. The arguments and the results of the methods use the original identifiers in both cases. Negative identifiers are only accepted with this option.

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

Notes

The path length is the sum of the lengths of the two half paths, from the source to the meeting vertex and from the meeting vertex to the target. It is not summed in the same order as by Dijkstra.run, so the two may differ in the last bits with non-integer weights. When several edges have the same tail and head vertices, only the one with the smallest weight is kept.

Minimum spanning tree of a graph seen as undirected, with Kruskal’s algorithm.

The edge (u, v) joins the vertices u and v whatever its direction. If the graph is not connected, the result is a minimum spanning forest: one minimum spanning tree per connected component.

Parameters:

  • edges (pandas.DataFrame or polars.DataFrame) – The edges of the graph, one row per edge. pandas dataframes can use NumPy or Arrow data types.

  • tail (str, optional (default='tail')) – Name of the column with the tail vertex of each edge. The vertex identifiers are integers, non-negative unless permute is True.

  • head (str, optional (default='head')) – Name of the column with the head vertex of each edge.

  • weight (str or None, optional (default='weight')) – Name of the column with the edge weights. The weights must be finite, they can be negative. With None, all the edges have a weight of 1: the result is a spanning forest with no particular property.

  • check_edges (bool, optional (default=False)) – Whether to check the edges before building the graph: column names, data types, missing and non-finite values.

  • permute (bool, optional (default=False)) – Whether to renumber the vertices internally, with contiguous indices starting from 0. Negative identifiers are only accepted with this option. The results use the original identifiers in both cases.

  • verbose (bool, optional (default=False)) – Whether to print the number of parallel edges that were removed.

Notes

Parallel and antiparallel edges: the graph is undirected, so the edges (u, v) and (v, u) join the same pair of vertices. Of all the edges joining a pair of vertices, only one with the minimum weight can be in the forest. It is returned with its tail and head as given. Self-loops are ignored.

Ties: among edges of equal weight, the one whose (tail, head) comes first in the order of the internal vertex indices is considered first, so the result is deterministic. Several minimum spanning forests may exist; they all have the same total weight.

The vertices are the tails and heads of the edges: with permute=False, the integers between 0 and the largest identifier that are not used by any edge are not vertices, and do not count as trees.

PageRank of the vertices.

The PageRank is the stationary distribution of a random walk that follows an outgoing edge with probability damping, chosen in proportion to the edge weights, and otherwise jumps to a vertex drawn from the personalization distribution (uniform by default). From a dangling vertex, without outgoing edge (or with zero out-weight), the walk always jumps to a vertex drawn from the personalization distribution.

This is networkx.pagerank with alpha=damping and dangling=None, except for the stopping criterion: NetworkX compares the change of the vector with n * tol, a threshold that grows with the graph while the vector sums to 1. Here tol does not depend on the number of vertices, so that the accuracy of the result does not either.

Parameters:

  • damping (float, optional (default=0.85)) – Damping factor, in [0, 1] (alpha in NetworkX).

  • personalization (dict or pandas.Series, optional (default=None)) – Teleportation weights of the vertices, as a mapping from vertex to a non-negative weight, normalized to sum 1. The vertices that are not given get 0. Uniform over the vertices if None.

  • tol (float, optional (default=1e-6)) – The iterations stop when the L1 norm of the change of the PageRank vector is smaller than tol. Since the error decreases by a factor damping at each iteration, about 90 iterations are needed with the default values.

  • max_iter (int, optional (default=1000)) – Maximum number of iterations.

  • output ({'numpy', 'pandas', 'polars'}, optional (default='numpy')) – Type of the result. ‘pandas’ returns a Series named ‘pagerank’ indexed by vertex (‘vertex_idx’), ‘polars’ a DataFrame with the columns ‘vertex_idx’ and ‘pagerank’.

numpy.ndarray, pandas.Series or polars.DataFrame – The PageRank of each vertex, summing to 1. The array is indexed by vertex identifier.

Graph validation¶

The classes above build the graph arrays themselves. The Cython functions of the library can also be called directly on arrays in CSR or CSC format, in which case the arrays are read without bounds checking. validate_graph checks such arrays once, before any number of runs.

edsger.commons.validate_graph(indptr, indices, data=None, nonnegative=True)¶

Check that a graph in CSR or CSC format is valid.

The graph algorithms of edsger read these arrays without bounds checking and only check, in constant time, that their arguments are consistent. This function checks the content of the arrays, in linear time. It is meant to be called once per graph, when the arrays do not come from edsger.path, before running the algorithms as many times as needed.

Parameters:

  • indptr (cnp.uint32_t[::1]) – Pointers in the CSR/CSC format: vertex_count + 1 elements.

  • indices (cnp.uint32_t[::1]) – Indices in the CSR/CSC format: one element per edge.

  • data (array-like, optional) – Edge weights in the CSR/CSC format: one element per edge.

  • nonnegative (bool, optional (default=True)) – Whether the edge weights should be non-negative, which is required by Dijkstra’s algorithm but not by the Bellman-Ford algorithm.

Raises:

ValueError – If the pointers do not start from zero, are not non-decreasing or do not end with the edge count, if an index is not smaller than the vertex count, or if the weights have the wrong length, contain a NaN or, when nonnegative is True, a negative value.

Test networks¶

edsger.networks.create_sf_network(dwell_time=1e-06, board_alight_ratio=0.5)[source]¶

Transit network of the example of Spiess and Florian (1989).

The four stops and four lines of the paper are expanded into a graph with 16 vertices and 24 edges: stop vertices, boarding and alighting vertices, and edges for boarding, alighting, riding, dwelling and transferring. Times are in seconds.

Parameters:

  • dwell_time (float, optional (default=1.0e-6)) – Time spent by a vehicle at a stop.

  • board_alight_ratio (float, optional (default=0.5)) – Boarding time and alighting time, each as a fraction of the dwell time.

Returns:

pandas.DataFrame – The edges, with the columns ‘tail’, ‘head’, ‘trav_time’, ‘freq’ and ‘volume_ref’. The last one is the edge volume given in the paper for a demand of 1 from vertex 0 to vertex 12.

References

Spiess, H. and Florian, M. (1989). Optimal strategies: a new assignment model for transit networks. Transportation Research Part B 23(2), 83-102.
